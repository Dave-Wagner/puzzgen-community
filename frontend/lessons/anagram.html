Anagrams: letters as a multiset

An anagram uses every supplied letter exactly once. The order changes but letter counts do not: two occurrences of a letter must stay two occurrences.

Try this puzzle in the playground →

A worked example

listen ↔ silent

Both words contain e, i, l, n, s, t. Sorting the letters produces the same signature. A clue such as “Making no sound” distinguishes silent from listen. Without the clue, both are reasonable answers.

This is a teaching example, not a promised output for seed 42.

How generation works

A seed selects a curated word and shuffles its characters. If the shuffle leaves the word unchanged, the generator rotates the characters. Easy supplies a clue and initial letter; Medium keeps the clue; Hard supplies the full curated vocabulary and accepts any vocabulary word with the same letter counts.

Keep kind, seed, difficulty, generator_version and content_version together for reproducibility. Seeds select combinations from finite content, so different seeds can repeat. The expanded default corpus is version 2. Send data.content_version when verifying or replaying; version 1 remains available. Version 2 IDs end in -content2.

Build the interface

Render letters as text or letter tiles and length as an explicit count. clue and first_letter are optional. In Hard mode, allowed_words is the vocabulary, not a list of guaranteed answers.

Use labeled inputs, visible focus, buttons with at least 44px touch targets, and a polite status region for results. Disable duplicate requests while busy. Keep answers attached to the puzzle they belong to; discard late responses after starting a new puzzle.

Make and check a request

This same-origin example uses a personal API key. Initialize personalKey in your local project and supply answer from your input. The key stays in memory; do not commit it. The built-in playground also supports signed-in sessions. For cross-origin projects, use your API origin and the documented bearer-key flow.

// Use a personal key in a local learning project. Never publish a privileged key.
const headers = { Authorization: `Bearer ${personalKey}` };
const seed = 42; // Exactly representable; retain this value for verification.
const response = await fetch(
  `/api/v1/puzzles/anagram?seed=${seed}&difficulty=medium`,
  { headers, signal: AbortSignal.timeout(10000) }
);
const puzzle = await response.json();
if (!response.ok) throw new Error(puzzle.error?.message ?? "Request failed");
// Render puzzle.data using textContent / framework text interpolation.
// Let the player supply answer. Its shape is described below.
const checked = await fetch("/api/v1/verify", {
  method: "POST",
  headers: { ...headers, "Content-Type": "application/json" },
  body: JSON.stringify({ kind: puzzle.kind, seed,
    difficulty: puzzle.difficulty, content_version: puzzle.data.content_version, answer }),
  signal: AbortSignal.timeout(10000)
});
const result = await checked.json();
if (!checked.ok) throw new Error(result.error?.message ?? "Check failed");
console.log(result.correct ? "Solved!" : "Try another answer");

Implementation patterns

Keep the displayed letter order separate from the answer string. React: derive remaining tiles from state; Vue: use computed; Svelte: use $derived; plain DOM: rerender from a small state object. Treat the API result as text, never HTML.

Start with idle, loading, ready, checking, success and error states. For 401, ask the player to sign in or supply a key. For 429 or 503, respect Retry-After and offer a retry; do not poll in a loop. On a failed generation, keep the old puzzle clearly labeled or clear it deliberately.

What the validator guarantees

Comparing sets of letters is wrong because sets discard duplicates. Compare frequency maps or sorted characters. Clued modes accept the curated target; Hard mode accepts any matching word in the supplied vocabulary, not an unrestricted English dictionary.

ASCII case and repeated/outer whitespace are normalized. Punctuation is not silently stripped. Wrong answer shapes are rejected. The response's uniqueness field describes the accepted-answer policy.

Your next experiment

Make selectable letter tiles with stable identities based on their original index. A word with repeated letters needs two separate tiles even though their labels match. Add Undo and keyboard entry.

Test your implementation

Replay the same seed twice and compare data. Submit a known answer and a wrong one. Try the keyboard alone, narrow mobile width, slow network, an expired key and a retry response. Reveal, then hide: checking must remain disabled while the answer is visible. For offline UI practice, save a generated response with its version fields and load that fixture without making more requests.

Content and reuse
