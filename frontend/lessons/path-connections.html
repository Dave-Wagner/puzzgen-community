DISCOVERY LAB / LEARN BY EXPERIMENTING

Path connections: local edges, global reachability

A bit mask compactly represents which sides of a tile have ports. Rotation preserves the type of piece. A valid local connection requires ports on both sides of an edge; a complete network also requires global connectivity.

A worked example

Mask 3 = north + east. Rotate clockwise → mask 6 = east + south.

This illustrates the rule, not a promised output for seed 42.

How construction works

A seeded randomized depth-first traversal constructs a spanning tree on a 3×3, 4×4, or 5×5 board. This gives every tile a place in a connected solution. Each tile is then independently rotated. The generator does not delete the path or replace pieces.

Keep kind, seed, difficulty and generator_version for replay. These seven generators use content_revision 1; this is separate from the version selector for the older language collection. Many seeds may produce equivalent challenges. Seeds and solution reveal are learning tools, not competitive anti-cheat.

What verification guarantees

Every submitted tile must be a rotation of its original piece. All ports must meet reciprocal neighbors, none may point off the board, and a traversal from the source must reach all tiles. Alternative valid orientations are accepted.

Build your own interface

Store integer masks in the model and derive glyphs from them. A clockwise turn uses ((mask << 1) & 15) | (mask >> 3). React/Vue/Svelte/plain DOM all benefit from separating this operation from rendering and animation.

Make loading, ready, checking, success and error states explicit. Disable duplicate submissions, keep a response attached to its original puzzle, and discard late replies after switching games. Use labeled controls, visible keyboard focus and a polite status region; a color alone must never carry the result.

Use the API

This same-origin personal-key example needs your own control-reading function. Use a personal learning key; do not publish a privileged key. The built-in playground can also use signed-in sessions. Cross-origin projects should use their API origin and the bearer-key flow.

const personalKey = "YOUR_PERSONAL_KEY"; // Keep local; never commit a privileged key.
const seed = 42;
const headers = { Authorization: `Bearer ${personalKey}` };
const response = await fetch(
  `/api/v1/puzzles/path-connections?seed=${seed}&difficulty=medium`,
  { headers, signal: AbortSignal.timeout(10000) }
);
const puzzle = await response.json();
if (!response.ok) throw new Error(puzzle.error?.message ?? "Load failed");
// Render puzzle.data; collect answer using the shape below.
// readAnswerFromYourControls is a function you implement in your interface.
const answer = readAnswerFromYourControls();
const checked = await fetch("/api/v1/verify", {
  method: "POST", headers: { ...headers, "Content-Type": "application/json" },
  body: JSON.stringify({ kind: puzzle.kind, seed, difficulty: puzzle.difficulty, answer })
});
const result = await checked.json();
if (!checked.ok) throw new Error(result.error?.message ?? "Check failed");
console.log(result.correct ? "Solved!" : "Try again");

Your experiment

Expose accessible port names beside the visual pipes. Show a local east/west leak in one color plus a text label. Then contrast that local test with a flood fill that checks every tile is reachable.

Review and test your implementation

Replay the same seed and compare data; try a known valid answer and a near miss. Exercise keyboard-only controls, narrow screens and request failures. Inspect the rejection rules above and test a boundary case. Save a versioned response as an offline fixture to develop without making repeated API calls.
